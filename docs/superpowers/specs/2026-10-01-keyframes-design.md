# Kadr — ключевые кадры и fade клипов

Дата: 2026-10-01 · Статус: **согласовано с владельцем в обсуждении (части 1–3); ждёт
проверки записанного текста**.
Подпроект 1 из дорожной карты «ключевые кадры → эффекты → титры → прокси → GPU».
Опирается на [архитектуру рендеринга](2026-09-30-render-architecture-design.md)
(M0–M6) и готовит почву для [системы эффектов](2026-09-30-effects-system-design.md)
(анимационные примитивы, дорожки Level 3).

## 0. Цель и границы

Пользователь анимирует позицию, масштаб, поворот, прозрачность, crop и цвет клипа
во времени и делает появление/исчезновение клипа ручками на таймлайне. Типичная
анимация из двух кадров сразу выглядит плавно; поведение при монтаже (trim, split,
скорость, slip, multicam) предсказуемо и никогда не «сдвигает» анимацию
относительно содержимого.

**Входит:** типизированная модель анимации, три домена времени, easing, вычисление
в evaluator, fade видео и аудио ручками и в инспекторе, команды с undo, UI
инспектора и таймлайна, MCP, миграция формата проекта, тесты.

**Не входит (заложено):** Auto/Bezier easing, анимация параметров эффектов
(`AnimValue`), automation дорожек (timeline-bound), fade через цвет (переходы и
рецепты), reverse, выделение отдельных кадров рамкой, отмена перетаскивания по Esc,
команды для AI-ассистента, ручки прямого манипулирования на превью.

## 1. Домены времени

Разные сущности живут в разных системах координат; это **разные типы**, а не одно
соглашение поверх `Time`.

| Домен | Тип | Что хранит | Что с ним делает монтаж |
|---|---|---|---|
| Source-bound | `SourceTime(Time)` — момент в исходном медиа | `Animation`; позже параметры эффектов, маски, трекинг | ничего: trim, move, speed, slip, split его не пересчитывают |
| Clip-bound | `Time` как длительность от видимого края клипа | `video_fade`, `audio.fade_*`; позже переходы на краях | только ограничение (§4) |
| Timeline-bound | `Time` на таймлайне | маркеры; позже automation дорожек и события проекта | уже есть |

- Всё время — целые флики (`kadr-core::Time`, `i64`). Переход между доменами —
  только через точные `Clip::source_time_at(t)` и `Clip::timeline_time_of(s)`
  (`mul_ratio`, без накопления f64). f64 появляется один раз — в прогрессе
  сегмента (§3.2).
- Newtype `SourceTime` не даёт перепутать домены при компиляции.
- **Статичные изображения** имеют синтетическое медиавремя (от 0, линейно);
  модель и отображение те же.

## 2. Модель данных (`kadr-project::animation`)

```rust
pub struct SourceTime(pub Time);

/// Ключ анимируемого свойства. В JSON — строка snake_case.
pub enum AnimParam {
    X, Y, Scale, Rotation, Opacity,
    CropLeft, CropRight, CropTop, CropBottom,
    Exposure, Contrast, Saturation, Temperature,
    // Позже: Effect { effect: EffectId, key: ParamKey } со значениями AnimValue
    // (f64 | bool | enum | colour) и правилом интерполяции по типу. Сейчас — только f64.
}

pub struct Keyframe {
    pub at: SourceTime,     // точное; к границам кадров в модели не привязывается
    pub value: f64,
    pub ease: Ease,         // кривая сегмента ПОСЛЕ этого кадра; у последнего кадра не используется
}

pub enum Ease { EaseInOut, Linear, EaseIn, EaseOut, Hold /* позже: Auto, Bezier { .. } */ }

pub struct Animation {
    tracks: BTreeMap<AnimParam, Vec<Keyframe>>,          // кадры отсортированы, `at` уникально
    unknown: BTreeMap<String, serde_json::Value>,         // §2.1
}

pub struct EdgeFades { pub fade_in: Time, pub fade_out: Time }

// Clip: + animation: Animation, + video_fade: EdgeFades
// (аудио продолжает использовать audio.fade_in / audio.fade_out)
```

### 2.1 Прямая совместимость: неизвестные свойства не теряются

`io::parse` отклоняет файлы с `format_version` новее своего (`TooNew`). Значит,
**новые `AnimParam` добавляются без повышения `FORMAT_VERSION`**, и более старая
сборка должна:

```
загрузить проект с неизвестным ключом → не выполнять его → сохранить → ключ и его данные на месте
```

Механизм: `Animation` сериализуется одной JSON-картой `{ ключ: дорожка }` своей
реализацией `Serialize`/`Deserialize`. Известный ключ разбирается в
`AnimParam` + `Vec<Keyframe>`; **неизвестный ключ сохраняется целиком как
`serde_json::Value`** (его дорожка может иметь другую форму, например будущие
не-f64 значения) и пишется обратно без изменений. Evaluator и UI неизвестные
дорожки не видят.

То же для `Ease`: неизвестный вариант кривой (например, будущий `bezier` с
параметрами) сохраняется как `Ease::Unknown(serde_json::Value)`, вычисляется как
`Linear`, в UI показывается «Другая» и не редактируется, пока пользователь не
выберет известную кривую.

Тест: JSON с реально неизвестным ключом (`"future_glow": [{ "at": …, "value": { "r": 1, "g": 0 } }]`)
и неизвестной кривой → `load` → `save` → `load` → эти фрагменты равны исходным как
JSON-значения (порядок ключей внутри объекта `serde_json` может нормализовать —
смысл данных не меняется).

### 2.2 Формат проекта и миграция

- `FORMAT_VERSION` 1 → 2. Иначе старая сборка молча проигнорирует `animation` и
  `video_fade` и при сохранении **потеряет** анимацию; с повышением она честно
  скажет «проект создан более новой версией».
- `migrate(value, 1)` переводит старое поле `keyframes: [{property, time, value,
  interpolation}]` в `animation`: известные `property` (`transform.x`,
  `transform.scale`, `color.exposure` …) → `AnimParam`; `time` (от `timeline_in`) →
  `SourceTime` через `source_in` и скорость клипа; `interpolation` `linear | hold |
  ease_in_out` → `Ease`. Неизвестные `property` уходят в `unknown`. Старое поле
  больше не пишется.

## 3. Вычисление

### 3.1 Easing (`kadr-core::ease`)

Общие кривые для анимации и будущих рецептов. `u ∈ [0, 1]`.

| `Ease` (JSON) | UI RU / EN | Формула |
|---|---|---|
| `ease_in_out` — **по умолчанию** | «Плавно» / "Smooth" | cubic in-out: `u < ½ ? 4u³ : 1 − (2 − 2u)³ / 2` |
| `linear` | «Линейно» / "Linear" | `u` |
| `ease_in` | «Разгон» / "Ease in" | `u³` |
| `ease_out` | «Торможение» / "Ease out" | `1 − (1 − u)³` |
| `hold` | «Удержание» / "Hold" | `0` при `u < 1` |

- Формулы — часть сохраняемой семантики проекта и закреплены тестами по точкам
  0, ¼, ½, ¾, 1. Другая кривая — **новый вариант**, а не правка старого.
- Заложено, не реализуется: `Auto` (монотонный кубический сплайн с непрерывными
  касательными по цепочке кадров — без остановки в каждом кадре) и
  `Bezier { out, in }`. Enum тегированный: новые варианты читаются без миграции.
- **Правило вставки:** кадр внутри сегмента `[k0, k1]` получает `k0.ease`
  (вставка не меняет характер существующего участка). Первый кадр свойства и кадр
  до первого / после последнего получают `EaseInOut`.
- **Reverse (на будущее):** easing определён по направлению source-сегмента; при
  обратном воспроизведении визуальный смысл `EaseIn`/`EaseOut` инвертируется.
  Решается вместе с reverse.

### 3.2 Значение свойства

`resolve(clip, param, t)`:
1. Нет дорожки → статическое поле клипа (`transform.scale`, `color.exposure` …).
2. Дорожка есть → статическое поле **не участвует**. `s = source_time_at(t)`.
   До первого кадра — его значение; после последнего — значение последнего;
   внутри `[k0, k1]`: `u = (s − k0.at) / (k1.at − k0.at)` (целые флики → один f64),
   `v = k0.value + (k1.value − k0.value) · ease(k0.ease, u)`.
3. Скрытые кадры (за In/Out клипа) участвуют в интерполяции.
4. Первый кадр свойства получает текущее значение этого свойства в точке, где его
   ставят. При удалении последнего кадра свойства статическое поле получает
   значение, которое свойство имело **в текущей точке редактирования (плейхеде)**
   непосредственно перед удалением, — изображение там не меняется.

### 3.3 Прозрачность и fade

```
final_opacity(t) = resolved_opacity(t) × fade(t)
```

`resolved_opacity` — статическая прозрачность или значение дорожки (§3.2), не обе
сразу. `fade` — clip-bound множитель, линейный. `d` — длительность кадра
последовательности, `in`/`out` — края клипа на таймлайне:

```
fade_in(t)  = F_in  = 0 ? 1 : clamp((t − in) / F_in, 0, 1)
fade_out(t) = F_out = 0 ? 1 : clamp((out − d − t) / F_out, 0, 1)
fade(t)     = fade_in(t) · fade_out(t)
```

Контракт: первый кадр fade-in и последний кадр fade-out полностью прозрачны;
нулевая длительность даёт множитель 1 без деления. Fade — это прозрачность от
края: на V1 при чёрном фоне визуально «из чёрного / в чёрный», на верхних
дорожках — растворение в нижележащие слои. Цвета у fade нет; «через чёрный /
белый / вспышка» — будущие переходы и рецепты.

Для аудио `audio.fade_*` работают как сейчас (огибающая громкости с точностью до
сэмпла); меняется только UI (ручки, §6.2).

### 3.4 Инварианты на границе вычисления

`Animation` хранит что угодно; нормализация — в evaluator:
- `opacity` → `[0, 1]`; `scale ≤ 0` → слой не выводится;
- `contrast ≥ 0`, `saturation ≥ 0`; `exposure`, `temperature` → диапазоны
  ползунков инспектора;
- crop: каждое значение → `[0, 1]`; `left + right ≥ 1` или `top + bottom ≥ 1` →
  видимой области нет, слой не выводится (нормальная ситуация, не ошибка);
- `rotation` не нормализуется по модулю 360: 0° → 720° — два оборота.

### 3.5 Отсечение

Правило: **не декодировать слой, если evaluator может доказать, что его вклад в
итоговый кадр равен нулю.** В текущей модели достаточное условие — `final_opacity
== 0`, пустой crop или `scale ≤ 0`. Будущие переходы и эффекты, которым нужны
пиксели источника при нулевой собственной прозрачности слоя, это доказательство
не проходят — оптимизация не становится ограничением архитектуры.

### 3.6 Где это в коде

- `kadr-core::ease` — кривые.
- `kadr-project::animation` — типы §2, `Animation::value_at(param, s) -> Option<f64>`,
  (де)сериализация с `unknown`, правило вставки; миграция — в `io::migrate`.
- `kadr-timeline::scene` — `clip_state_at(clip, t) -> ClipState { transform,
  color, fade }` с нормализацией §3.4; дальше существующий путь `Layer`.
- `kadr-scene`, `kadr-render`, `kadr-playback` **не меняются**: сцена уже несёт
  placement, opacity и `ColorAdjust` на каждый кадр.

## 4. Монтаж

| Операция | Анимация (source-bound) | Fade (clip-bound) |
|---|---|---|
| Move, ripple-сдвиг | не меняется | не меняются |
| TrimStart | не меняется (кадры за краем скрываются, при расширении возвращаются) | ограничение, сначала `fade_in` |
| TrimEnd | не меняется | ограничение, сначала `fade_out` |
| Speed (начало на месте) | не меняется: кадры растягиваются/сжимаются вместе с медиа | ограничение, сначала `fade_out`; длительности fade не масштабируются |
| Slip | не меняется: анимация едет вместе с содержимым | не меняются |
| Split | **полная копия** `Animation` в обе половины | `fade_out` левой и `fade_in` правой → 0 |
| SwitchAngle (multicam) | все `at` сдвигаются на ту же разницу sync-смещений, что и source-диапазон | не меняются |

- **Ограничение fade** (инвариант `fade_in + fade_out ≤ duration`) — после каждой
  команды, меняющей длительность. Пока сумма помещается — значения не меняются;
  иначе уменьшается fade на изменённом крае, второй — только когда первый дошёл до
  0. Undo возвращает исходные значения (команда хранит клип).
- **Split:** сразу после разреза обе половины на каждом кадре дают ровно тот же
  рендер, что исходный клип (одна функция от одного `SourceTime`, включая скрытые
  хвосты). Дальше половины независимы: правка кадра во второй не меняет первую —
  у каждой своя копия. Копия выбрана вместо `Arc` + copy-on-write: данных мало
  (десятки кадров), `split_clip` уже делает `clone()`, а при сериализации общие
  данные всё равно разделились бы.

## 5. Команды `EditEngine` (все с undo)

| Команда | Источник |
|---|---|
| `SetKeyframe { clip, param, at: SourceTime, value, ease: Option<Ease> }` | `◆`; отпускание ползунка анимированного свойства; `None` → правило вставки |
| `RemoveKeyframe { clip, param, at }` | повторный клик по `◆`, меню ромбика |
| `MoveKeyframes { clip, moves: Vec<(AnimParam, SourceTime, SourceTime)> }` | перетаскивание ромбика; при совпадении времени с существующим кадром того же свойства — отказ с понятным сообщением, без слияния |
| `SetKeyframeEase { clip, param, at, ease }` | меню интерполяции |
| `ClearAnimation { clip, params: Vec<AnimParam>, reset_to_defaults: bool }` | «Сбросить анимацию свойства» (`false`), «Сброс» секции (`true`) |
| `SetClipProperty(VideoFade(EdgeFades))`, `SetClipProperty(Audio(..))` | ручки и поля fade |

- **Кадр «в плейхеде»** — кадр, у которого `|timeline_time_of(k.at) − playhead| <
  ½ кадра последовательности`. Это правило только для UI: сохранённый `SourceTime`
  точный и к кадрам не привязывается.
- **Сброс секции** = одним шагом undo удалить дорожки свойств секции **и** вернуть
  их статические значения к значениям по умолчанию (не к последнему анимированному).
- Перетаскивание (ползунок, ручка fade, ромбик) меняет клип «вживую» без записи в
  историю (существующий механизм инспектора) и даёт **одну** команду при отпускании.
- Метки истории в RU/EN: «Ключевой кадр: Масштаб», «Fade In: 0,5 с → 1 с» и т. п.

## 6. Интерфейс

### 6.1 Инспектор

- Справа от каждого анимируемого ползунка — `◀ ◆ ▶`:
  `◇` серый — нет анимации; `◇` акцентный контур — анимация есть, кадра в плейхеде
  нет; `◆` залитый — кадр в плейхеде. Клик по `◆`/`◇` ставит или снимает кадр.
- Если у свойства есть кадры, движение ползунка ставит или обновляет кадр в
  плейхеде (без «секундомера»).
- `◀ ▶` — к предыдущему/следующему **видимому** кадру свойства; неактивны, если
  такого нет. Скрытые кадры доступны после расширения клипа и через MCP.
- Анимированное свойство — акцентная точка у названия; ползунок показывает
  значение в плейхеде.
- **Частота обновления инспектора** при воспроизведении — около 10 Гц (только
  отрисовка UI); на паузе и при скраббинге — сразу. С частотой вычисления
  анимации (каждый кадр в evaluator) не связана. Инспектор не должен «дёргаться».
- Правый клик по строке: «Интерполяция ▸» (5 вариантов, отмечен текущий; для кадра
  в плейхеде), «Сбросить анимацию свойства».
- Секция «Появление и исчезновение» (видео и аудио): «Появление», «Исчезновение»
  в секундах с кадровой точностью; максимум каждого — длительность клипа минус
  другой fade. Значения синхронны с ручками таймлайна.
- «Сброс» секции — §5.

### 6.2 Таймлайн

Hit-testing и перетаскивание — в Rust (`Hit`, `Drag` в `timeline_ui.rs`), Slint
только рисует.

- **Ручки fade** (видео и аудио): кружки в верхних углах клипа; видны при наведении
  или выделении, при `fade > 0` — всегда (вместе с существующей диагональю).
  Шаг — кадр последовательности для видео, для аудио тоже кадр (сэмпловая
  точность огибающей сохраняется в модели). Ограничение — длительность минус
  другой fade. Живой предпросмотр во время перетаскивания, подсказка «Появление
  0:00:12», одна команда при отпускании. Зона захвата не меньше 10 логических
  пикселей и не перекрывается зоной trim (проверяется в маленьком окне).
- **Ромбики**: вдоль нижнего края клипа — по одному ромбику на каждое точное
  `SourceTime`, где есть кадр хотя бы одного свойства.
  - Ромбики ближе 6 px сливаются **только при отрисовке** (кластер); данные не
    объединяются, при увеличении масштаба ромбики снова разделяются.
  - Hit-testing работает с реальными моментами: клик по кластеру выбирает
    **ближайший реальный момент** к курсору. Перетаскивание двигает только кадры
    этого одного точного момента (все свойства в нём); соседние моменты кластера
    не затрагиваются.
  - Клик — выделить клип и поставить плейхед на момент. Перетаскивание —
    `MoveKeyframes` с шагом кадр последовательности, одна запись в undo.
  - Правый клик: «Интерполяция ▸» (для всех свойств этого момента), «Удалить
    кадры».
  - Скрытые кадры за краем — шеврон `‹` / `›` у соответствующего края.
- **Клавиши**: Alt+← / Alt+→ — предыдущий/следующий видимый кадр выделенного
  клипа (сейчас сочетания с Alt в `keys.rs` не заняты; одиночный Alt и меню окна
  на Windows проверяются при приёмке). Замена сочетания модель не затрагивает.
- **Не в V1:** выделение кадров рамкой и Delete по выделенным кадрам; отмена
  перетаскивания по Esc (сейчас нет ни у одного перетаскивания — если вводить,
  то сразу для всех).
- Все строки — RU и EN через `crates/i18n/locales/*.json`.

## 7. MCP

- Операции `edit`: `set_keyframe`, `remove_keyframe`, `move_keyframes`,
  `set_keyframe_ease`, `clear_animation`, `set_video_fade`.
- Время: для обычных (видимых) кадров — `at_ms` на таймлайне внутри клипа; сразу
  при разборе переводится в точное `Time` с привязкой к ближайшей границе кадра
  последовательности (правило полукадра, как у `add_transition`), затем в
  `SourceTime`. Для скрытых кадров и особых случаев — `source_ms` (переводится в
  точный `SourceTime`). Миллисекунды внутри не хранятся.
- `get_state` по клипу: `video_fade { fade_in_ms, fade_out_ms }` и
  `animation: { param: [{ at_ms, source_ms, value, ease, visible }] }`.
- `docs/mcp.md` дополняется грамматикой.

## 8. Тесты

| Уровень | Что проверяем |
|---|---|
| `kadr-core::ease` | контрольные точки каждой кривой; `ease(0) = 0`, `ease(1) = 1`; монотонность |
| `animation` | `value_at` до/между/после кадров; `Hold`; наследование easing при вставке; первый кадр без скачка; удаление последнего кадра без скачка в плейхеде; serde round-trip |
| совместимость | round-trip **реально неизвестного** ключа и неизвестной кривой (§2.1); миграция формата 1 → 2 со старым `keyframes`; файл формата 2 в сборке формата 1 → `TooNew` |
| split — свойство | для случайных анимаций, скоростей и точек разреза: `clip_state_at` обеих половин на каждом кадре **точно** равен исходному; правка одной половины не меняет другую |
| монтаж | trim/speed/slip/move не трогают кадры; SwitchAngle сдвигает их на sync-разницу; все правила ограничения fade (§4) |
| fade | первый кадр fade-in и последний fade-out прозрачны; `F = 0` → 1; `final_opacity = 0` → слой не в сцене |
| сцена | инварианты §3.4 |
| пиксели | экспорт короткого клипа с анимированной прозрачностью и fade: значения пикселей на контрольных кадрах |
| undo | каждая команда §5 в `EditEngine`; перетаскивание = одна запись |
| производительность | `kadr-bench scene`: 10 клипов × 13 анимированных свойств, цель ≤ 0,1 мс на кадр в evaluator. **Не** pass/fail тест в `cargo test`: цифра в бенчмарке и документе замеров, регрессия сравнивается с прошлым прогоном |

**Живая приёмка через `kadr-mcp`** (реальные клипы, скриншоты RU и EN, большое и
маленькое окно) — не только наличие элементов, но и ощущение:
- первый кадр создаётся без визуального скачка;
- анимация «Плавно» действительно выглядит плавно при воспроизведении;
- перетаскивание ромбика сразу отражается в превью;
- trim не сдвигает анимацию относительно содержимого;
- split визуально ничего не меняет;
- смена скорости корректно растягивает/сжимает анимацию;
- ручки fade легко захватываются в маленьком окне и не спорят с trim;
- инспектор не дёргается при воспроизведении;
- RU и EN не ломают раскладку;
- Alt+← / Alt+→ работают и не активируют меню окна.

## 9. Порядок реализации (для плана)

1. `kadr-core::ease` + `kadr-project::animation` (типы, serde с `unknown`,
   `value_at`, вставка) + миграция формата.
2. Evaluator: `clip_state_at`, fade, инварианты, отсечение; тесты сцены и split.
3. Команды `EditEngine` + правила монтажа §4 (trim, speed, split, SwitchAngle).
4. Инспектор: `◀ ◆ ▶`, живое редактирование анимированных свойств, секция fade.
5. Таймлайн: ручки fade (видео + аудио), ромбики, кластеры, шевроны, клавиши.
6. MCP + `docs/mcp.md`.
7. Бенчмарк evaluator, живая приёмка, ревью Opus.
