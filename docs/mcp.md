# Kadr MCP — управление через Claude

Kadr можно подключить к Claude Code / Claude Desktop как MCP-сервер: Claude
видит окно (скриншоты, дерево элементов), кликает и печатает по-настоящему
(через маршрутизацию ввода Slint) и вызывает семантические команды Kadr
(импорт, монтаж, экспорт, отмена/повтор — всё через `EditEngine`, поэтому
попадает в историю undo с префиксом «Claude: »).

## Как подключить

```
claude mcp add kadr -- "C:\путь\к\video-editor\target\debug\kadr-mcp.exe"
```

Или для релизной сборки — путь к установленному `kadr-mcp.exe` рядом с
`kadr.exe`. `kadr-mcp` — отдельный бинарник, который Claude Code запускает
сам и говорит с ним по stdio (JSON-RPC 2.0, `initialize` →
`notifications/initialized` → `tools/list` / `tools/call`).

Опционально: `KADR_DATA_DIR` — переопределяет каталог данных (там же, где
Kadr ищет свой `mcp/<pid>.json`); `KADR_EXE` — путь к `kadr.exe`, если он не
лежит рядом с `kadr-mcp.exe`.

## Режимы

- **Ваше открытое окно.** Если Kadr уже запущен и «Разрешить управление
  через MCP» включено, `kadr-mcp` находит его через файл обнаружения и
  подключается к нему — Claude видит и трогает именно то окно, что открыто у
  вас.
- **Headless.** Если живого инстанса нет, `kadr-mcp` сам запускает
  `kadr.exe --headless`: обычное окно Kadr, но за экраном, без кнопки на
  панели задач, никогда не активируется, не трогает ваш файл автосохранения
  (свои автосохранения в `recovery-headless`, старше 7 дней удаляются при
  следующем запуске headless), не пишет ваш `settings.json` (недавние
  проекты, раскладка панелей, язык) и `ai-settings.json` (в него дописывается
  только расход на AI). Расход за месяц общий для всех экземпляров: любая
  запись файла складывает его с тем, что уже на диске, а перед проверкой
  месячного лимита окно подтягивает расход скрытых экземпляров и не выводит звук. Такой инстанс завершается, когда сессия MCP
  заканчивается (закрытие stdin), а также если `kadr-mcp` убит или упал: на
  Windows он в Job Object с kill-on-close, плюс сам Kadr раз в 2 с проверяет
  pid родителя (переменная окружения `KADR_PARENT_PID`; старый флаг
  `--parent-pid` тоже понимается) и выходит, сбросив журнал на диск, если
  родителя нет.
- **Какой инстанс выбирается.** При первом вызове: ваше окно, если оно
  отвечает (из нескольких — запущенное последним), иначе уже живой headless,
  иначе новый headless. Явно — `list_instances` и `use_instance { pid }`.
- **Живость и переключение.** Инстанс считается живым, пока жив его процесс
  и его bridge-порт принимает соединения; `ping` отвечает поток bridge, а не
  UI, поэтому открытый нативный диалог или долгая работа не делают окно
  «мёртвым». Если вызов не успел — ошибка `busy_timeout` (запрос может
  выполниться позже — проверьте `get_state` перед повтором). Если процесс
  завершился или порт отказывает в соединении, `kadr-mcp` сам подключается
  к другому инстансу (по тем же правилам выбора, при необходимости запуская
  headless); вызов, на котором это обнаружилось, не выполняется и
  возвращает `instance_gone` с pid старого и нового инстанса — так ничего не
  попадает в другой проект незаметно.

## Настройка «Разрешить управление через MCP»

Находится в настройках Kadr, по умолчанию включена. Изменение вступает в
силу только после перезапуска Kadr — после него выключенная настройка не
даёт стартовать обоим серверам: `SLINT_MCP_PORT` не экспортируется (а
унаследованный из окружения — удаляется; сервер Slint не стартует) и не
поднимается bridge Kadr — `mcp/<pid>.json` не создаётся. `kadr --headless`
при выключенной настройке сразу завершается с кодом 3, не создавая окна, а
`kadr-mcp` сообщает «MCP control is disabled in Kadr settings (Settings →
General)».

## Безопасность

- Всё только на loopback (`127.0.0.1`), никаких сетевых слушателей наружу.
- UI-порт (встроенный MCP-сервер Slint 1.18) **не защищён токеном** — это
  особенность самого Slint; защита — loopback + проверка заголовка `Origin`.
  Это осознанный компромисс, принятый на этапе проектирования.
- Bridge-порт Kadr (Kadr-инструменты: `get_state`, `import_media`, `edit`,
  `export`, …) требует `Authorization: Bearer <token>`; токен — 32 случайных
  байта в файле обнаружения `<data dir>/mcp/<pid>.json`, который читает
  только `kadr-mcp` (тот же пользователь). Токен сравнивается за постоянное
  время; обслуживается только `POST /rpc` (другой путь — 404, другой
  метод — 405).
- Claude ничего не подтверждает лишний раз: если MCP включён, он может
  сохранять поверх файлов, экспортировать, удалять медиа, запускать платный
  AI — как и обычный пользователь. Бюджетные лимиты AI из настроек
  продолжают действовать.

## Обзор инструментов

### Sight (наблюдение)
| Инструмент | Источник | Что даёт |
|---|---|---|
| `ui_get_element_tree`, `ui_find_elements_by_id`, `ui_query_element_descendants` | Slint | дерево элементов окна, поиск по id |
| `ui_take_screenshot` | Slint | PNG снимок окна |
| `ui_list_windows`, `ui_get_window_properties` | Slint | список окон и их свойства |
| `get_state` | Kadr | проект, дорожки/клипы (id, тип, тайминги, линковка, мультикам, ключевые кадры, эффекты), выделение, playhead, открытые диалоги, тосты, задачи, чат ассистента. Геометрию элементов на экране даёт `ui_get_element_tree` |
| `list_effects` | Kadr | библиотека эффектов: id рецепта, названия (ru/en), категория, цель (`clip` — видеоклипы), параметры с типом, диапазоном или вариантами и значением по умолчанию |
| `get_log` | Kadr | последние строки лога с флагом паник; `level` — `error`/`warn`/`info`/`debug`/`trace` (другое значение — ошибка `bad_params`) |
| `get_frame` | Kadr | кадр (PNG) на заданное время — ровно то, что показывает превью: все слои (картинка в картинке, логотипы), переходы, кадрирование, поворот, прозрачность, цвет, режим «до» (bypass). Рендерится новым конвейером в качестве экспорта (свой resolver в режиме экспорта, не на UI-потоке; превью при ½ и ¼ рисует то же, но быстрее и мягче). Не шире `max_w` (960) и, если задано, не выше `max_h`, в пропорциях холста последовательности, без увеличения. Пропуск и места, где только звук, — чёрный кадр (раньше была ошибка); в ответе `layers` (сколько слоёв в сцене, 0 = пропуск), `offline` (есть медиа без файла — на кадре красная заглушка), `bypass`. Пустой таймлайн и время за концом — ошибка `not_found` с объяснением |
| `get_perf` | Kadr | телеметрия превью. Окно последних 600 кадров: `frames`, `dropped` (опоздавшие и ненужные кадры), перцентили p50/p90/p99/max в мс — `total_ms` (показанные кадры), `decode_ms` (все кадры: декодирование оплачено и у пропущенных), `composite_ms`, `present_ms`, `seek_ms` (от смены playhead до показа последнего кадра). С последнего сброса: `total_frames`, `total_dropped`, `dropped_pct` (доля от `total_frames`). `frame_allocs_per_frame`, `frame_copies_per_frame`, `mb_copied_per_frame` — выделения и копии кадровых буферов; `renderer` — всегда `cpu` (единственный путь; поле оставлено для совместимости). `present_ms` — передача готового буфера UI-потоку (без копии), а копия означает, что Slint ещё держал буфер кольца и его пришлось скопировать на потоке плеера; на UI-потоке кадры не копируются. `reset: true` читает и обнуляет окно и счётчики одной операцией |

Ссылки на элементы (`elementHandle`) живут, пока жив сам элемент: Kadr
обновляет списки на месте, поэтому смена выделения или правка не делают
ссылки устаревшими, включая вложенные списки (пометки на клипе, пункты
плана ассистента). Клипы, медиа, корзины, задачи, уведомления и недавние
проекты сопоставляются по id: элемент остаётся за своим объектом, а ссылка
на удалённый клип умирает (ошибка «element that was destroyed») — найдите
его снова через `ui_find_elements_by_id`. Списки без id (дорожки, деления
линейки, сообщения чата) сопоставляются по позиции: после добавления или
удаления строки ищите элемент заново.

Координаты элементов внутри всплывающих окон (контекстные меню) Slint
отдаёт относительно самого всплывающего окна, а не главного: пункты меню
нажимайте по ссылке (`ui_click_element`), а не через `click_at`.

### Семантические команды (Kadr)
`edit`, `undo`/`redo`, `select`, `set_playhead`, `playback`, `import_media`,
`place_media`, `project` (`new`/`open`/`save`/`save_as`), `export`
(`preset` 0–2, `resolution` 0–3 — целые индексы, см. схему), `ui`
(`menu` — id пункта меню), `assistant`. Грамматика операций `edit` (все типы
и поля) — в описании инструмента, которое видит Claude.

`add_transition` (`EditCommand::AddTransition`): `at_ms` привязывается к стыку
(`timeline_out` одного клипа == `timeline_in` следующего на той же дорожке),
если ровно один такой стык лежит не дальше полукадра (по частоте кадров
секвенции) от `at_ms` — так миллисекундно округлённое время клиента попадает
точно на стык при 29.97. Если стыка рядом нет или их несколько, `at` остаётся
как передан (переход без пары клипов на стыке вычислитель считает устаревшим).

`set_transform` задаёт статические значения. Если у переданного свойства есть
ключевые кадры, статическое значение не действует (значение берётся из ключей),
поэтому операция отклоняется: `edit_rejected` «<param> is animated (keyframes);
use set_keyframe or clear_animation» (`rotation_deg` называется `rotation`).
Так же отвечает и встроенный ассистент.

Ключевые кадры и затухания клипа: `set_keyframe`, `remove_keyframe`,
`set_keyframe_ease`, `move_keyframes`, `clear_animation`, `set_video_fade`
(реализация — `apps/editor/src/mcp_anim.rs`). Момент задаётся одним из двух
способов: `at_ms` — время на таймлайне внутри клипа (привязывается к кадру
секвенции, вне клипа — отказ) или `source_ms` — время в источнике (так
адресуются и скрытые ключи за краями клипа; для `move_keyframes` это
`from_ms` / `from_source_ms`, цель `to_ms` — всегда время на таймлайне внутри
клипа). Существующий ключ находится в пределах половины кадра от заданного
времени (для `at_ms` — только видимые ключи клипа, время берётся как есть, без
привязки к кадру), поэтому миллисекундно округлённое время из `get_state` при
29.97 попадает точно в свой ключ — и в `remove_keyframe`/`set_keyframe_ease`/
`move_keyframes`, и в `set_keyframe`: если ключ этого свойства есть в пределах
половины кадра, он обновляется (новый рядом не создаётся); только когда рядом
ничего нет, ключ ставится на привязанное к кадру время (`at_ms`) или точно на
`source_ms`. Повтор того же значения и той же кривой у `set_keyframe`, та же
кривая у `set_keyframe_ease` — отказ «no change» (иначе в истории осталась бы
пустая запись). `value` проверяется по свойству (иначе `edit_rejected`
«<param> out of range a..b»): `x`, `y` — пиксели секвенции, ±20000; `scale` —
множитель 0.01..16 (1 = 100 %); `rotation` — градусы, ±3600; `opacity` — 0..1;
`crop_left`/`crop_right`/`crop_top`/`crop_bottom` — доли кадра 0..1; `exposure`
— EV, −2..2; `contrast`, `saturation` — множитель 0..2 (1 = без изменений);
`temperature` — −1..1; число эффекта (`param: "fx:<effect-id>:<key>"`) — диапазон
из `list_effects`. Ключевые операции отклоняются с причиной для клипов на
невидео-дорожках и на заблокированных дорожках; `move_keyframes` — также если у
одного из двигаемых свойств в целевом моменте уже есть ключ. Все
миллисекундные поля — целые не больше 10 000 000 000 по модулю, иначе
`edit_rejected`. `move_keyframes` без `param` (или с `null`) двигает все
свойства в этом моменте; перенос в тот же момент — отказ «no change».
`remove_keyframe` последнего ключа свойства оставляет его значение в клипе
статическим значением. `clear_animation` без `params` сбрасывает только
анимированные свойства и числа эффектов клипа (статические значения не
трогает; ключи эффекта из более новой версии Kadr остаются, как и у
`move_keyframes` без `param`); клип без анимации или список `params` без
анимированных свойств — отказ; значения после сброса — по умолчанию (у числа
эффекта — значение по умолчанию из `list_effects`) или картинка в момент
`keep_ms`. Статическое значение числа эффекта вне его диапазона (ключи из
чужого файла) движок молча обрезал бы, поэтому MCP отказывает с причиной:
`clear_animation` с таким `keep_ms` и `remove_keyframe` последнего такого
ключа. `set_video_fade` (`fade_in_ms?`, `fade_out_ms?`) — затухания картинки от
краёв клипа, только для клипов на видеодорожках (звуковые отклоняются);
значения привязываются к кадру секвенции (совсем малое станет 0, а если это
ничего не меняет — отказ «no change»), отрицательные отклоняются,
`fade_in + fade_out` не больше длительности клипа.

Как и остальные операции `edit`, эти видят проект до вызова: ключ, созданный
одной операцией, нельзя адресовать следующей в том же вызове (сообщение «no
keyframe there» напоминает об этом; нужную кривую передавайте в `ease` самого
`set_keyframe`); две `set_video_fade` для одного клипа в одном вызове считаются
от старых значений, поэтому задавайте оба затухания одной операцией; перенос,
смена скорости и обрезка клипа в том же вызове до ключевых операций не меняют
геометрию, с которой те считаются, — делайте их отдельными вызовами.

Эффекты клипа (`apps/editor/src/mcp_fx.rs`, команды ассистента в
`crates/ai/src/command.rs`): `add_effect` (`clip_id`, `recipe` из
`list_effects`, `params?` — числа, строки вариантов, точка `{x, y}` в долях
кадра клипа, момент `{at_ms}` — время таймлайна внутри клипа — или
`{source_ms}`; пропущенные получают значения по умолчанию: сила 0,6, центр,
середина клипа). Один экземпляр рецепта на клип: повторный `add_effect`
заменяет параметры (тот же `effect_id`, ключевые кадры эффекта удаляются),
повтор без изменений — отказ «no change». `set_effect` (`effect_id`,
`params?`, `enabled?`) сливает переданные параметры; параметр с ключевыми
кадрами — отказ «<key> is animated» (как `set_transform`); эффект из более
новой версии Kadr (`known: false`) не меняется, только удаляется или
переносится; момент, присланный обратно в том виде, как его показал
`get_state` (`{at_ms, source_ms, visible}`, миллисекунды округлены вниз), —
тот же сохранённый момент, то есть «no change». `remove_effect` удаляет эффект
вместе с его ключевыми кадрами, `move_effect` (`to` — позиция в списке, 0 —
применяется первым) меняет порядок. Числа эффектов анимируются обычными
ключевыми операциями с `param: "fx:<effect-id>:<key>"` и диапазоном из
`list_effects`; число эффекта из более новой версии Kadr не анимируется (отказ
с причиной). `get_state` показывает у клипа `effects`: `{id, recipe, version,
enabled, known, progress, params}`.

`get_state` в каждом клипе показывает `video_fade` (`fade_in_ms`,
`fade_out_ms`), `animation` — по свойствам (числа эффектов — под ключом
`fx:<effect-id>:<key>`) массив ключей `{at_ms, source_ms, value, ease,
visible}`: `ease` — ключ кривой или `"unknown"`, `visible` — ключ внутри клипа
(скрытые — за его краями — адресуются только через `source_ms`).

Пункты меню, которые в обычном UI открывают системные диалоги (открыть
файл/папку, сохранить как, экспорт), в MCP заменены прямыми инструментами:
вместо клика по «Открыть проект…» — `project { "action": "open", "path": ... }`,
вместо «Импортировать…» — `import_media { "paths": [...] }`, вместо диалога
экспорта — `export { ... }`.

Инструмент `ui` (`menu`) явно отклоняет id меню `new`/`open`/`save`/
`save_as`/`import`/`export`/`exit` — вместо них используйте `project`/
`import_media`/`export`. Он же отклоняет `fullscreen` в headless-инстансе
(окно за экраном не может стать полноэкранным) и `logs` (открыл бы
Проводник на рабочем столе пользователя; вместо него — `get_log`).

### Utility
`wait_idle` (фоновые задачи завершены и кадр превью загружен),
`list_instances`, `use_instance`. Метод протокола MCP `ping` поддерживается
(ответ `{}`), но это не инструмент.

## Известное ограничение

Реальный ввод в Kadr идёт через маршрутизацию событий Slint
(`ui_click_element`, `ui_dispatch_key_event`, …), а не через уровень ОС
(`SendInput`). Это значит:

- нативные диалоги файловой системы (открыть/сохранить файл) недоступны для
  ввода через MCP — для них есть прямые Kadr-инструменты (`project`,
  `import_media`, `export`), которые их обходят;
- трансляция ОС → winit → Slint (реальные драйверы клавиатуры/мыши,
  раскладки на уровне ОС) не тестируется этим путём — `layout_text`
  компенсирует это для шорткатов, завязанных на физическую раскладку, но не
  проверяет саму трансляцию ОС.
